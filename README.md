# 助学款到账缺口与校内周转额度

业务资料均为合成记录。表头字段及跨表引用见 `fixtures/format.json`。

## 数据说明

钱均为整数分，day 是学期开始以来的日期序号。charges 负数表示抵减，同一 charge 的截止日以资助中心确认的延期为准；减免在 known_day 前不能花用。transfers 的 cents 是汇总金额，可用金额以 allocations 和用途确认日为准。正反银行回单不得互相复制成另一学生的已收款。空到账日表示观察结果仍开放，历史时点按 last_seen_day 截断。
支出以 budget 所在缴费期的额度计算，paid 与 committed 占额，proposed 为待审。已付垫款的回收以真实到账或确认减免为依据，承诺到期未付可以释放。经手台账只列 synthetic student 编号。

CSV 使用 UTF-8、逗号分隔，无引号与内嵌换行。未提供的字段是空字符串，作为关系值的 `-` 表示不适用。多值字段用竖线分隔，数值和日期单位见业务约定。

## 资料检查

使用 Node.js 22.23.4，依赖仅为 Node.js 标准库。运行 `npm ci --ignore-scripts --offline` 准备工作区。

运行 `npm run check:materials` 检查合成交接资料的字段与记录引用。运行 `npm test` 检查交接资料的读取和校验。

## 台账核算与校内周转

`src/` 提供台账核算，每次执行都重新载入台账，可反复运行；同一观测日重算结果一致，可用当周证据重现对外告知的结论。

- `npm run review -- handler --as-of 18`：经办视图。按缴费窗核对实收、承诺、实际缺口与预计缺口；列出周转额度占用与可继续安排的金额、未分配款、冲正影响到的后续安排、垫付处置建议（释放/暂缓/回收）、误记风险与提醒，并附当周证据清单。
- `npm run review -- student --student S1 --as-of 18`：学生视图。仅本人的应缴（含生效抵减与延期后截止日）、已可用款、学校垫付、待核原因。
- `npm run review -- forecast --as-of 18`：未确认到账按路径给出的可用性区间与历史支撑；放款方式无对应历史时提醒经办人。

省略 `--as-of` 时以台账中最晚可观测日为准；`--fixtures DIR` 指定台账目录。

核算口径：可用款以 allocations 拆分与用途确认日为准，不把银行放款日当作可用日；批量汇款未拆分部分不当作学生已足额；学生账户未确认可转缴的回单不并入学校实收；抵减只在 known_day 后冲减应缴，不写成现金；历史案例按 last_seen_day 截断，仍未结清的按未结清处理。垫付处置只依据真实到账、确认减免与承诺有效期，新预测不会自动收走已答应的垫付。
